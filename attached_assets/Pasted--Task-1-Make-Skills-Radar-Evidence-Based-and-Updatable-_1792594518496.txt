# Task 1 — Make Skills Radar Evidence-Based and Updatable

I want to improve only the Skills Radar feature in my existing FutureReady Workforce project.

The current Skills Radar contains synthetic skill-history records. The project also already has DOSM integration through `dosmData.ts` and a reviewed quarterly snapshot in `dosm-jmi-2026.ts`.

Inspect the existing implementation first and reuse working code wherever possible.

## 1. Connect real Malaysian labour-market evidence

Use the existing OpenDOSM API integration for regularly updated national labour-force indicators.

Use the official DOSM Job Market Insights releases for verified quarterly online job-offering data, including occupations where detailed figures are available.

Sources:
- OpenDOSM: https://open.dosm.gov.my/data-catalogue
- DOSM Job Market Insights Q1 2026: https://www.dosm.gov.my/portal-main/release-content/big-data-analytics-job-market-insights-q12026
- DOSM Job Market Insights Q2 2026: https://www.dosm.gov.my/portal-main/release-content/big-data-analytics-job-market-insights-q22026

Do not duplicate the existing data-fetching service or create another competing DOSM API.

## 2. Add a dated AI-advancement signal source

Investigate whether the official Ministry of Digital or MDEC announcement pages offer a reliable public API, RSS feed, or another supported way to retrieve updated announcements.

Sources:
- Ministry of Digital: https://www.digital.gov.my/en-GB/siaran
- MDEC: https://www.mdec.my/press-releases

If a reliable machine-readable source is available, connect it through the existing backend.

If not, propose a robust alternative before introducing fragile page scraping. Do not pretend a static list is automatically updating.

Show each signal's actual title, publication date, source, and link. AI announcements may be displayed as qualitative evidence, but do not turn them into invented numerical skill-demand scores or forecasts.

## 3. Improve the Skills Radar interface

Replace the synthetic skill-history chart in the real-data view with clearly labelled, evidence-backed panels or charts.

Separate these concepts:

- Labour-force indicators.
- Online job offerings by occupation.
- AI-advancement announcements.
- Existing global skill-posting frequencies from the Qarera dataset, where useful.

Do not label unemployment statistics as skill demand.

Display the source, reference period, publication date, retrieval/update timestamp, and data limitations.

A refresh control must actually request updated data. Include loading, empty, error and stale-data states. Never report a successful refresh when a request failed.

## 4. Keep all data honest

- Do not invent missing values, dates, sources or trend percentages.
- Do not present manually authored observations as live data.
- Clearly distinguish published observations from qualitative interpretations and future scenarios.
- Do not claim that DOSM's broad occupational figures measure individual technology skills.
- Preserve the Qarera dataset's attribution and limitations.

## 5. Keep the change narrowly scoped

Modify only the Skills Radar page and the backend/data-service files required for this feature.

Do not:
- Change career-matching scores or APIs.
- Modify CV upload, OCR or skill extraction.
- Change the Learning Roadmap or SDG mapping.
- Add an LLM, RunPod, paid API or database.
- Redesign unrelated navigation or dashboard pages.

Before editing, tell me which files you intend to change.

## 6. Test and report

Run relevant API tests, typechecks and production builds.

Verify that the radar retrieves actual data, displays the correct source and reporting period, handles failed refreshes honestly, and works in a browser.

If possible, verify the deployed workflow after publishing. Clearly distinguish completed tests from anything that remains unverified.

Report the actual data sources integrated, which panels now use real data, and which trend information still lacks a suitable source.
