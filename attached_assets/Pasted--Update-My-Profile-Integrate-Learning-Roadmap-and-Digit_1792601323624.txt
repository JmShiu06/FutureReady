# Update My Profile: Integrate Learning Roadmap and Digital Twin

Modify the existing FutureReady Workforce application to integrate the Skills Profile, Learning Roadmap, and Digital Twin into one My Profile category.

Inspect the current codebase first. Reuse existing components, data structures, scoring logic, and services wherever possible. Do not rebuild working features unnecessarily.

## 1. Navigation and My Profile structure

Keep Career Explorer as a separate navigation category.

My Profile should contain three main sections:

1. **Skills Profile** — CV upload, extracted skills, skill evidence, and current proficiency levels.
2. **Learning Roadmap** — target career selected from Career Explorer, skill gaps, recommended learning tasks, and learning progress.
3. **Digital Twin & Progress** — actual learning progress, confirmed skill improvements, career-readiness comparisons, and the existing hypothetical skill simulator.

Remove unused basic profile fields, such as name and achievements, only after verifying that they are not needed elsewhere.

Remove the old standalone Learning Roadmap and Digital Twin navigation entries only when their functionality is fully accessible under My Profile. Preserve Career Explorer and other necessary navigation.

## 2. Keep Career Explorer separate

Users should continue exploring different careers in Career Explorer.

For each role, show available required or listed skills, the user's matching skills, and their remaining skill gaps, based on the existing dataset and matching logic.

Provide an explicit action such as **"Build my learning roadmap"**.

Only when the user chooses this action should that career become the active target for their roadmap. Exploring another career must not silently replace the existing target.

## 3. Preserve the existing Learning Roadmap progress bar

**This is a mandatory requirement: retain the existing roadmap progress card and progress bar. Do not remove it, simplify it away, or replace it with an unrelated progress indicator.**

Move the existing progress card into My Profile > Learning Roadmap and preserve its current visual design and functionality, including:

- The heading and progress summary.
- The completed-milestones counter, such as "1 of 2 milestones".
- The existing horizontal progress bar and its visual styling.
- Total estimated learning cost.
- Budget information and budget-comparison functionality.
- Priority skills associated with the learning plan.

Reuse the existing calculations and data sources. Do not hardcode the example values shown in the screenshot; the values must reflect the user's actual roadmap.

Keep the existing introductory message or equivalent explanation that completing a milestone tracks progress only and does not automatically change profile skill levels.

### Progress bar behaviour

- The progress bar represents completion of roadmap milestones.
- Completing a milestone updates the completed count and percentage according to the existing roadmap logic.
- Reopening or uncompleting a milestone updates the progress consistently.
- Repeated clicks must not create duplicate completions.
- Progress must persist after page refreshes and navigation, using the existing persistence architecture.
- Changing the target career should update the roadmap and its progress appropriately without accidentally deleting the completion history of other targets.
- The cost and budget information must remain separate from the milestone-completion percentage.

Keep the current progress bar's appearance as closely as possible. Refactor only what is necessary to place it within the new My Profile layout.

## 4. Connect the Learning Roadmap to the selected career

When the user selects "Build my learning roadmap" in Career Explorer, display that role as the current roadmap target in My Profile.

Show the available required skills, confirmed user skills, skill gaps, and learning recommendations relevant to that target.

Organise recommended resources into practical tasks. Each task should show available information such as its title, provider, verified resource URL, related skills, estimated duration, cost, and completion status.

Reuse the current roadmap implementation and preserve existing milestone functionality. Do not invent real courses, providers, prices, or learning-resource URLs. Clearly label demonstration data if verified course information is unavailable.

## 5. Connect completed learning to Digital Twin

When a user completes a course or milestone:

- Save its completion status.
- Update the roadmap progress bar.
- Record which learning activities the user has completed.
- Display those activities as learning progress in Digital Twin.
- Recalculate relevant roadmap completion and learning summaries.

**Do not automatically increase the user's skill proficiency merely because a milestone or course is marked complete.**

Instead, allow the user to review and confirm any proposed proficiency change. Record the confirmed new proficiency separately from the course-completion record.

When proficiency changes are confirmed, Digital Twin should compare the starting and current skill profiles and recalculate the career-readiness score using the same existing scoring formula and the same target-role requirements.

Display:
- Starting and current skill levels.
- Confirmed skill improvements.
- Completed learning activities.
- Remaining skill gaps.
- Starting and current career-readiness scores.
- Point or percentage-point change, clearly defined.

Do not fabricate improvement points or present the score as a probability of employment.

## 6. Preserve the existing hypothetical Digital Twin

Keep the existing what-if simulator, where users can manually adjust hypothetical skill levels and see the simulated effect on their score.

Clearly distinguish:
- Actual learning and confirmed skill improvements.
- Hypothetical skill changes made only for simulation.

Resetting a simulation must not erase completed milestones, completed courses, or confirmed proficiency changes.

The simulator should use the user's current confirmed skills as its starting point, while keeping hypothetical edits separate and unsaved to the actual profile until the user independently confirms a real skill update.

## 7. Persistence and consistency

Inspect the current data architecture and reuse it.

Keep these records logically consistent:
- Confirmed skill profile.
- Active roadmap target.
- Roadmap milestones and their completion states.
- Course completion history.
- Resource-to-skill mappings.
- Starting and current progress snapshots.
- Hypothetical simulation state.

Ensure progress is preserved on refresh. Prevent duplicate completion events and duplicate proficiency increases. Do not introduce unnecessary database infrastructure if the existing architecture already supports this workflow.

## 8. Acceptance tests

Verify that:

1. Career Explorer remains a separate navigation category.
2. Selecting a career for a roadmap requires explicit user action.
3. The existing roadmap progress card and progress bar remain visible under My Profile.
4. The milestone counter and percentage update correctly.
5. The existing estimated cost, budget comparison, and priority-skills information remain available.
6. Completing or reopening a milestone updates progress consistently.
7. Completed milestones do not automatically increase proficiency levels.
8. Confirmed proficiency changes update the Digital Twin comparison using the existing scoring formula.
9. Actual progress and hypothetical simulation remain separate.
10. Refreshing or navigating away does not lose persisted progress.
11. Existing CV extraction, career matching, and roadmap functionality continue to work.

Run relevant tests, TypeScript checks, and production builds. At the end, report the files changed, the progress-bar logic preserved, the persistence method, test results, and any remaining limitations. Do not claim the public deployment works unless it has been tested separately.
