# FutureReady Workforce — Official Data Integration, Milestone 1

You are a senior TypeScript backend developer and labour-market data engineer working on my existing FutureReady Workforce hackathon application.

## Project context

The current project already contains:
- React/TypeScript frontend.
- Express backend.
- Career matching endpoints.
- Dataset-based skills matching.
- Synthetic job listings.
- Future Skills Radar with synthetic market observations.
- Career Digital Twin, roadmap and scenario interfaces.

Inspect the latest code before making changes. Preserve the existing UI and APIs.

## Overall planned evidence sources

1. TalentCorp Malaysia — MyMahir Malaysia Critical Occupations List (MyCOL).
2. Department of Statistics Malaysia — OpenDOSM and Job Market Insights.
3. O*NET — Occupation and skills requirements.
4. arXiv — AI research RSS feeds.
5. ESCO — Occupation and skill normalisation.

Do NOT integrate everything in one large task.

### Requirements

1. Inspect the existing Express architecture, data models, services and frontend Skills Radar.
2. Verify that every chosen dataset is accessible and document its permitted use.
3. Implement a server-side DOSM data adapter.
4. Support monthly labour-force observations using the official API or published CSV.
5. Create a small, reviewed, date-stamped dataset of comparable occupation-level statistics from the official DOSM Job Market Insights reports where reliably available.
6. Keep official published figures separate from synthetic example data.
7. Store each observation's dataset ID, source URL, observation date, publication date, retrieval time, geographical coverage and methodology notes.
8. Validate numeric fields, date formats, units and occupation identifiers.
9. Implement backend caching and sensible timeouts so users are not dependent on a live external request for every page load.
10. Add a safe refresh mechanism with proper failure handling.
11. Connect the existing Skills Radar to these real records.
12. Display clear source attribution and an evidence-status indicator.
13. Allow comparisons between compatible observation periods.
14. Never infer occupation-specific skill demand from national unemployment statistics.
15. Do not invent missing observations or interpolate unsupported growth percentages.
16. Keep existing synthetic data as an explicitly identified fallback.
17. Add automated tests for source loading, parsing, invalid records, refresh failures and trend calculations.
18. Do not modify RunPod integrations or build another career-matching engine.

### Expected results

The user can visit the existing Skills Radar and:
- View genuine DOSM statistics.
- See the source and dates.
- Compare historical observations where supported.
- Distinguish observed data from synthetic examples.
- Understand the data limitations.

Provide an explanation of how these observations can be connected to the existing career-matching system in Milestone 2 without mixing skill readiness and labour-market demand.

### Quality checks

Run typechecks, builds and relevant tests.

Report which data was genuinely retrieved, which was manually imported and which remains synthetic.

Do not claim a successful live integration unless you have tested a real refresh against the official source.

Do not proceed to TalentCorp, O*NET, ESCO or arXiv integration without my approval.
