# Task — Audit FutureReady Workforce Data and Backend Integration

I want to understand which datasets and backend services are actually powering my updated FutureReady Workforce application before adding more data.

**IMPORTANT: This is an audit-only task. Do not modify, create, delete, merge, or overwrite any files. Do not install dependencies or change deployment settings.**

## 1. Audit the existing datasets

Inspect the entire existing project and identify every dataset, JSON/CSV file, synthetic data source, mock-data module, and hard-coded data collection.

I have previously supplied a career-matching dataset named `career_roles_test.json`, containing 15 role families, 450 role-skill records, and 227 distinct skill names.

Verify:
- Whether this dataset exists in the current project.
- Its exact file path.
- Whether it is loaded by the Express backend or another service.
- Which features actually consume it.
- Whether production uses the same dataset as development.
- Whether another dataset has replaced or duplicated it.

Do not assume a dataset is integrated just because a file or feature exists.

- Whether calculations run in the frontend or backend.
- Whether the feature is fully functional, partially implemented, or only a demonstration.
- Whether it uses `career_roles_test.json`.
- Whether an API endpoint actually exists and is called.

## 3. Audit existing API integration

Inspect the Express backend, API specification, generated clients, and frontend service layer.

Pay particular attention to:
- `POST /api/career/match`

- Job Search endpoints.
- Any other APIs used by the updated frontend.

Verify which endpoints exist, which are called by the UI, and which are merely planned interfaces or unused code.

Check whether the updated frontend has disconnected any previously working CV upload/OCR, career-matching, or Job Search functionality.

Do not report an endpoint as working solely because its route exists. Use tests or safe requests where practical.

## 4. Identify actual data gaps

Recommend which additional datasets are genuinely needed, based on the current features and data sources.

Prioritise:

For each proposed dataset, explain which feature would use it, what evidence it would provide, and whether the existing project already has an equivalent source.

Distinguish Malaysian labour-market evidence from international skill-posting frequencies. Do not invent figures, source URLs, licences, or records.

Return a concise report with:

**A. Dataset inventory:** Name, file path, source, licence, geography, period, and intended use.
